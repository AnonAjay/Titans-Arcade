# Titans-Arcade benchmarks

Create the named Conda environment once, then install the pinned dependencies:

```powershell
conda create -n titans-arcade-benchmark python=3.12 pip -y
conda activate titans-arcade-benchmark
pip install -r requirements.txt
```

Run the suite from the Titans-Arcade root:

```powershell
python benchmarks/run_all.py
```

The runner executes three deterministic, hardware-independent paths: one floor
homography point transform, one Station A 10x10 hazard update, and one Station B
six-joint pose comparison. Each path records three warm-ups and 30 timed samples
by default. Use `--runs 100 --warmups 5` for more samples; fewer than 30 timed
samples or three warm-ups is rejected.

Every run writes a timestamped CSV under `benchmarks/results/raw/`. Each row
contains the exact JSON input, output, elapsed time, and whether it was a warm-up
or a timed sample. `benchmarks/results/EVIDENCE.txt` is replaced with the latest
summary, `pytest.txt` records the suite output, and `failure-case.json` records
the malformed outbox and invalid floor calibration cases. The fixtures are labeled
`reviewed=false`; they are author-written and should be reviewed before treating
correctness conclusions as final.

The benchmark runner gives each pytest subprocess a new temporary directory.
The repository's plain pytest configuration pins one reusable `.pytest_tmp`
path, which failed to clean itself on a repeated Windows run in the fresh-clone
check. Run the one-command benchmark entry point for isolated repeatable test
runs; the report records the exact fresh-clone sequence.

The malformed outbox and collinear calibration tests are strict expected
failures. They demonstrate that the current StationNetworkClient silently
removes an invalid JSON line and the current FloorMapper accepts collinear
corners. Production code remains unchanged in this benchmark task. Once either
behavior is fixed, its strict xfail will become an XPASS failure and should be
removed while keeping the assertion as a normal regression test.

These are CPU-local microbenchmarks, not camera or whole-application timings.
The runner does not open the webcam. It reports no baseline because no equivalent
prior implementation was available to interleave on this machine. It does not
download the MediaPipe model. To measure capture/inference/render stages, run on
the event station with a connected camera and a reviewed set of labeled frames.

## MediaPipe pose correctness benchmark

The current catalog's `landmarks_norm` and `target_angles` were generated by
MediaPipe. They are useful to reproduce the current pipeline, but they are not
independent ground truth and must not be used to claim pose accuracy.

The current reference-image run emits all six game angles for 36/36 images
(95% Wilson interval for output yield: 90.36%–100%). This measures whether the
indexer emitted outputs, not whether those angles are correct. See
`results/POSE_DETECTION.txt` and `results/pose_detection_raw.csv`.
The current indexer also drops landmark visibility before angle extraction, so
six numeric fields do not establish that the underlying joints were visible.
An AI-assisted visual screen of the source/overlay pairs rated 23/36 plausible,
13 uncertain, and 0 obvious mismatches. This is a single ChatGPT visual review,
not ground truth; its ratings remain `reviewed=false` in
`results/visual_pose_audit.json`.

Create an annotation template from the current 36-image catalog:

```powershell
python benchmarks/pose_accuracy.py --init
```

To reproduce only the output-yield measurement after installing the MediaPipe
model, run:

```powershell
python benchmarks/pose_accuracy.py --coverage-only
```

Independently annotate the 12 MediaPipe joint points listed in
`benchmarks/pose_labels.json` for a representative subset and mark the dataset and each pose
`reviewed: true` only after review. The evaluator compares MediaPipe's six game
joint angles to angles computed from those independent points, reports the
per-joint raw CSV, detection coverage, angle error, and Wilson confidence
intervals. It refuses incomplete labels and detects image changes by SHA-256.
Unreviewed labels produce `PROVISIONAL` metrics. The production catalog is
read-only during evaluation.

At present there are no independent labels, so pose correctness is **NOT
MEASURED**. See `results/POSE_ACCURACY.txt` and
`issues/pose_accuracy.md`. Do not claim 90% accuracy until the reviewed set and
its evaluation meet a predeclared criterion. A score among accepted poses must
be shown alongside detection coverage so rejecting difficult images cannot
inflate the headline.
